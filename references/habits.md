# 习惯决策树（完整版）

夜班无人值守时，人不在场——本文件把"人类用户平时的取舍习惯"固化成三档处置规则。原则：**宁可保守记录，不可冒险扩大**。

## 〇、开工预检（人还在场时，把该问的问在前面）

**时机**：接到夜班任务列表、挂 Goal **之前**——此时人还在电脑前。

**收尾必做（预检回答完之后）**：执行 SKILL §0 第 8 条**挂机门禁**——四项实测（Goal / 续行 / `every_seconds` 心跳 / run 登记），全 YES 才输出 `✅ NIGHT-SHIFT READY TO LEAVE` 块放人走；任一项 NO 就明说"现在挂机不会自恢复 + 需要你现在做什么"。**这一步不能跳**：用户发完消息就离开，门禁缺失时第二天看到的就是"任务从没开始"（2026-11-01 实测教训）。

**做什么**：扫一遍任务列表，把"夜里没法自己解决的事"一次性问完，写进 `night-shift/preflights/<日期>.md`（按日期留档不覆盖；模板见 templates.md §0）。只问三类：

1. **需求歧义**：任务描述存在两种以上理解方式的；
2. **设计取舍**：方案 A/B 且分叉影响后续方向的（不适合按默认走，或返工成本高的）；
3. **预测依赖**：预判某个功能大概率要装新包的 → 列出**包名 + 出处**（官方文档/GitHub 项目/知识库调研结果），请用户**当场预授权**或否决。

**问法要求**：

- **一次性批量问完**，不挤牙膏式一问一答——回答者只有这一小段时间；
- §三默认表能覆盖的**不进预检单**，预检单只收"必须现在定"的；
- 每项带推荐倾向（"我建议 A，理由 X"）——用户可以只回一句"都按你建议的"，照记，来源标 `预检默认`。

**用户答复的三种落法**：

| 答复 | 后续执行 |
|---|---|
| 明确指示（含当场点名"允许装 X"） | 最高优先级，夜班照办，DECISIONS 标 `预授权` |
| "按你建议的 / 都行" | 按预检单建议执行，DECISIONS 标 `预检默认` |
| 没答 / 没时间答 | 挂起；夜里真遇到时落回 §三 默认，仍拿不准则 blocked |

**价值**：把人工决策点从"夜里半路卡住干等天亮"平移到"睡前 5 分钟"——夜班最大的浪费不是装不成依赖，是任务 blocked 空转。

### 〇-1 依赖引入分治规则（按任务类型）

**第一步永远先判任务类型**——这是装不装包的分水岭：

| 任务类型 | 判据 | 依赖处置 |
|---|---|---|
| **修复类** | 修 bug / 重构 / 性能修复——目标是**恢复既有行为** | **红线：永不装新依赖**。修复总有纯本地替代路径（临时实现、用已有依赖拼、内联用例）；装包会改变故障面、掩盖真因。绕不开 → blocked + 简报说明 |
| **新增功能类** | 引入需求方明确要的**新行为**——目标是**产生新东西** | 走下方档 2 来源白名单，或预检预授权 |

**修复类没有例外，且"重新定性"必须用户点头**：若一个"修复"真的只能靠新依赖完成，它就不是修复——但**夜间不得自行重定性**：记 DECISIONS.md 标 `疑似重定性` → **不装包、任务 blocked** → 简报"待定性"；只有预检单里用户明确同意（或白天裁定）后，才按功能类走档 2。防止用一句"这其实是功能"绕开装包红线。

**新增功能类 · 档 2 来源白名单**，四条**同时**满足才可自主安装：

1. **有出处**：包名在开工调研阶段记录过来源（官方文档 / GitHub README / `knowledge/research` 已有笔记）——凭空冒出的包名不算；
2. **锁版本**：精确版本安装（`zod@3.24.1`，不用 `^` / `latest`），防上游突变；
3. **卫生合规**：只走默认 registry、装前拼写核对防 typosquat、禁 `--force` 类旗标、禁全局/用户级安装与改包源（AGENTS.md §2.1 依赖豁免四条件之一）；
4. **可回滚**：装完立即单独 `chore(deps): add <pkg>` commit，与功能代码分离——晨检一眼 diff，不满意一条 revert 摘掉。

**装包卫生（预授权与白名单同样适用）**：

- 只走默认 registry；装前拼写核对（防 typosquat）；
- 禁 `--force` 等改写依赖状态的旗标；
- 装成功 ≠ 完成：功能仍须走完整验证协议（verification.md）；
- BRIEF"待拍板"区**单列依赖变更行**：包名@版本 + 出处 + commit hash + `git diff package.json` 摘要。

**lockfile 还原不在此列**：`npm ci` / `pnpm install --frozen-lockfile` 只复现既有依赖图、不改变它——修复与新功能一律自由区（2026-10-30 用户确认维持）。

## 一、自由区（直接做，不问，不记）

满足全部条件即可放手干：

- 目标在**当前工作区（cwd）内**
- 操作**可逆**（改错了 git/备份能恢复）
- 属于完成任务所必需
- 不涉及下述禁区任何一条

具体包括：

| 类别 | 允许的操作 |
|---|---|
| 源码/测试 | 创建、修改、重命名工作区内文件；写/改测试 |
| 验证 | 运行测试、构建、lint、typecheck、启动本地服务、无头浏览器验证 |
| 依赖 | **仅按已有 lockfile 还原**（`npm ci` / `pnpm install --frozen-lockfile` / `uv sync --frozen`）——这不改变依赖图 |
| 提交 | 夜班/无人值守模式下（AGENTS.md §4.1.1 commit 豁免已落地）`git add` + `git commit`，一任务一提交，信息按 commit-message 规范 + 注明测试状态；**push 仍禁区** |
| 状态文件 | 写 `night-shift/*`（原始层）；写 `knowledge/` 下的**原始层新文件**（`summaries/`/`pitfalls/`/`research/`）。`knowledge/patterns/`（派生层）**只在提炼 pass 写**，夜间不写 |
| 备份式清理 | 把文件**移动**到 `$DSH_HOME/trash/<时间戳>/` 代替删除（仅限本次任务刚产生的临时物） |

## 二、禁区（永不执行，记入简报等人）

| 类别 | 具体 | 替代动作 |
|---|---|---|
| **装依赖** | 修复类任务的一切装包；不满足 §〇-1 四条件（出处/锁版本/卫生/可回滚）的功能类装包 | 修复类 → 换实现（标准库/已有依赖/手写）；功能类 → 补齐四条件或记简报四要素（缺什么/建议包名/装完落哪/改哪些文件）等人批 |
| **删除** | 删工作区内既有的非本任务产物文件/目录；删工作区外任何文件 | 改为移动到 trash 备份目录；或在简报列出"建议清理清单" |
| **git 危险动作** | `push`、`commit --amend`、`rebase`、`reset --hard`、`clean -fdx`、`push --force` | commit 后即止，push 永远留给人 |
| **越界写** | 写工作区（cwd）以外的任何位置：`C:\`、`D:\` 其他目录、`~/.dsh` 配置、`~/Documents` 等 | 只读可以（任务指名的单点），写一律等白天 |
| **C 级目标** | 系统目录、凭据文件（`*.pem`/`.key`/`.ssh` 等）、注册表、其他盘根目录 | 无替代，直接放弃该思路 |
| **系统级** | 装软件、改环境变量/PATH、动启动项、`Stop-Process -Force` 系统进程 | 记简报 |

**禁区判断从严**：路径拿不准算越界，操作可逆性拿不准算删除。

## 三、拿不准（默认倾向表）

触发条件："两种做法都说得通，但用户不在，问不了"。处置：**选默认 → 记 DECISIONS.md → 继续**。

| 场景 | 默认倾向 | 理由 |
|---|---|---|
| 设计取舍（方案 A/B） | 选**更简单、更贴仓库现有惯例**的那个 | 讲话原则："最短路径就是最佳路径"；改起来便宜 |
| 缺某个依赖才能继续 | **先判任务类型**（§〇-1）：修复类永不装，换实现或 blocked；功能类查预授权 → 查来源白名单 → 都不满足则 blocked | 装包是分治规则不是一刀切；四条件缺一即禁区 |
| 测试失败原因不明 | 先复现（写最小复现用例）再修，**不猜** | 讲话教训：agent 自信指认 smoking gun 十有八九是幻觉 |
| 修复涉及禁区操作 | 换一条不碰禁区的路；无路 → blocked + 简报说明 | 底线不因任务重要性松动 |
| 任务间发现顺手的小问题 | **不做**，记入简报"顺手发现"清单 | 不扩大任务范围 |
| 两晚任务列表冲突/重复 | 做更新的那个，另一个记简报 | git 历史已是真实来源 |
| 网络波动/模型重试耗尽 | 默认 5 次重试耗尽 = **该轮失败**，会话空闲等下一轮心跳继续（**不重启进程、不改全局配置**）；连续 ≥3 轮同类失败 → 判环境不可用，停心跳 + 标 blocked + 简报说明 | 无限重试是 provider 级配置会拖累白天所有会话；模型不可用时重试无意义 |
| 改动可能影响工作区外构建 | 只改工作区内副本，简报注明"工作区外未同步" | 越界写是禁区 |

## 四、决策日志格式（DECISIONS.md）

每条记录固定五要素，追加写入，不改历史：

```markdown
## [ISO 时间] 任务：<任务名>
- 情况：<触发"拿不准"的具体情形>
- 备选：<考虑过的方案>
- 选择：<实际做的>
- 理由：<一句话，引 habits.md 的哪条默认>
- 来源：<预授权 | 预检默认 | 白名单 | 默认表 | 重新定性>
- 影响面：<改动了什么文件；可逆性如何；涉及依赖则附包名@版本+出处+commit>
```

晨检时逐条扫，**按来源级别从低到高看**（`默认表` < `白名单` < `预检默认` < `预授权`——前两级是没经你眼的，重点复核）：同意的默认 → 无需动作；不同意的 → **不要只改这一次的结果，把新习惯写回本文件对应行**（这就是习惯蒸馏的闭环）。

**回写纪律（原始数据保留原则在习惯层的落点）**：改本文件任何一行时，必须同时在 DECISIONS.md 追加一条"习惯回写"记录——**旧行原文 → 新行原文 + 日期 + 理由**（模板见 templates.md §2）。本文件的行是破坏性编辑（旧行被覆盖、git 历史又不常提交），DECISIONS.md 是习惯演化史的原始层：没有这条记录，"当初为什么改"就断了。**习惯只增改不删行**：确认某条默认彻底错了 → 行内标 `（已废弃 YYYY-MM-DD，见 DECISIONS）` 保留原文，不物理删除。

**改哪一份、怎么回流**：夜班改的是**安装副本** `~\.dsh\skills\night-shift\references\habits.md`；仓库基准（`<skill-repo>/night-shift/references/habits.md`）**不会自动同步**——回写后必须在当天 BRIEF 加一条"**待同步 skill**：habits.md 第 N 行"，用户白天复制回仓库（提交/push 由用户手动做）。否则下次同步会用旧仓库版本覆盖掉你的改进。
