## 4. 升级候选 `night-shift/ESCALATION.md`（追加写）

```markdown
- [2026-10-30T03:02:00+08:00] 场景：项目 X 没有验收命令，每次现拼 | 这次怎么处理的：按 verification.md §三拼了 tsc+eslint+vitest | 为什么 skill 不够：每次现拼有漂移风险，该固化成 scripts/verify.ps1 一条硬命令
```

## 5. 检查清单（晨检 5 分钟用法）

1. 打开 `night-shift/briefs/<今日>.md` 扫"一句话总结 + 任务清单"表（1 分钟）
2. 抽查 1-2 条决策：同意 → 忽略；不同意 → 改 `habits.md` 对应默认行，**并按 §2"习惯回写记录"把旧行原文→新行原文追加进 DECISIONS.md**（习惯蒸馏闭环 + 原始留档，2 分钟）
3. 检查"待拍板"：能当场批的批掉（依赖四要素齐全才批）（1 分钟）
4. 看 commit、抽查证据路径，没问题手动 `git push`（1 分钟）
5. 顺手把"顺手发现"排进今晚任务列表（1 分钟）

## 6. 任务清单 `BUG-BOARD.md`（工作区根；SKILL §2 第 2 条强制落文件）

> **名字里的 BUG 是历史惯例，不是限制**：本文件是**全部计划任务的看板**——缺陷、功能、重构、文档、杂务都放这里，靠状态标记区分。它真正起作用的是"**唯一清单文件**"这个角色。**清单解析优先级（显式指令 > 约定文件名）**：① prompt 指定的任何路径（`今晚计划.md` / `TODO.md` / `.txt`）**直接成为清单本体**，原地编辑、不复制、不改名（⚠️ 会被写状态标记，别指向不想改的文件）→ ② 工作区已有的 `BUG-BOARD.md` / `TODO.md`（**仅当没有指定路径时**才用）→ ③ 都没有才新建 `BUG-BOARD.md`。第①必须压过第②，否则上一夜残留的全 ✅ 旧清单会盖过你今晚指定的清单，等于任务从没开始。清单只存在于对话里时，才新建 `BUG-BOARD.md` 并把对话里的任务抄进去。

**状态设计**（只改标记、不删条目；四种状态覆盖夜班全部结局）：

| 标记 | 含义 | 必须补写 |
|---|---|---|
| `- [ ]` | 待办 | — |
| `- [x]` | ✅ 完成 | 链到 `night-shift/summaries/<…>.md` |
| `- [~]` | ⚠️ 完成有残留 | 写明残留是什么、后续怎么办 |
| `- [!]` | ❌ blocked | 写明卡在哪、需要什么才能解锁 |

```markdown
# BUG-BOARD <YYYY-MM-DD 起>

- [ ] fix-sidebar-lag：侧边栏滚动卡顿（验收：复现步骤 + 帧率对比）
- [x] update-readme：补安装说明 → night-shift/summaries/20261101-update-readme.md
- [~] add-export-btn：导出按钮已上，但缺自动化测试，残留：补一条 e2e
- [!] deploy-staging：卡在凭据，需用户提供 `STAGING_TOKEN` 才能继续
- [ ] add-export-csv：导出 CSV（预授权 zod@3.24.1，来源：官方文档）
```

规则：

- **每轮心跳第一件事 `read` 本文件**，据其判断"下一项做什么"，不要凭对话记忆；
- 完成一条就地改标记 + 补链接，**绝不删条目**（原始层纪律，晨检复核与溯源用）；
- 用户中途可以自己改本文件（加任务 / 删任务 / 调优先级），夜班下一轮 `read` 即生效，**不需要发消息打断**；
- 条目一行一条、可执行；细节写在条目下一行（缩进 2 空格）。
